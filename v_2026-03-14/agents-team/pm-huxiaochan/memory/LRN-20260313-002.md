## [LRN-20260313-002] PM 主动推进项目流程

**Logged**: 2026-03-13T00:41:00+08:00
**Priority**: critical
**Status**: resolved
**Area**: config

### Summary
PM 必须主动管理和推进整个项目流程，前一项工作完成且通过评审决策后，立即叫醒下一个责任人并推进到下一阶段

### Details

#### 问题背景
在【待办任务记录】项目中，老大明确指出：
- PM 不能被动等待团队成员汇报
- PM 需要主动追踪每个阶段的完成情况
- 阶段完成后要主动叫醒下一个责任人
- 确保项目流程不中断、不等待

#### 正确流程
```
PLANNING 完成 → 叫醒 Arch → DESIGNING 开始
DESIGNING 完成 → 叫醒 FE/BE → DEVING 开始
DEVING 完成 → 叫醒 QA → TESTING 开始
TESTING 完成 → 叫醒 OCA → RELEASE 评审
```

#### 错误示范 ❌
- 等待 Arch 主动提交技术评审
- 等待 FE/BE 主动汇报开发完成
- 等待 QA 主动要求测试
- 等待 OCA 询问进度

#### 正确示范 ✅
- PRD 完成后 → 立即叫醒 Arch 进行技术评审
- 技术评审通过后 → 立即叫醒 FE/BE 开始开发
- 开发完成后 → 立即叫醒 QA 开始测试
- 测试通过后 → 立即叫醒 OCA 进行发布评审

### Suggested Action

#### 1. 建立阶段检查清单
每个阶段结束时自问：
- [ ] 本阶段交付物是否完成？
- [ ] 是否通过评审/决策？
- [ ] 下一个责任人是谁？
- [ ] 是否已叫醒下一个责任人？
- [ ] 下一阶段是否已启动？

#### 2. 主动追踪机制
- 每 30 分钟检查一次各角色状态
- 发现阻塞立即协调解决
- 超时 15 分钟未响应 → 上报 OCA
- 超时 30 分钟 → 上报老大

#### 3. 叫醒话术模板
```
@Arch 胡小架：PRD 已完成，请进行技术评审
- 评审重点：技术选型、架构设计、风险评估
- 评审时间：30 分钟
- 评审输出：TDD 文档

@FE 胡小前：技术评审已通过，请开始前端开发
- 开发内容：UI 界面、交互功能
- 开发时间：X 小时
- 交付物：可运行的前端代码

@QA 胡小测：开发已完成，请开始测试
- 测试依据：PRD + 测试用例
- 测试时间：X 小时
- 交付物：测试报告
```

#### 4. 状态看板更新
每次叫醒后更新：
- 当前阶段：[阶段名]
- 当前责任人：[角色 + 姓名]
- 开始时间：[时间]
- 预计完成：[时间]
- 状态：[进行中/已完成/阻塞]
